# Documentation Guidance

Use these guidelines when creating or updating Markdown documentation.

## General Principles

- Follow the bottom-line-up-front (BLUF) principle: present the most important information first, then provide supporting details.
- Prefer clear, direct language and explain project-specific terms when they first appear and use the same term for the same concept consistently throughout the documentation.
- Make the smallest documentation change that fully addresses the request; avoid unrelated rewrites.

## Structure and Organization

- Give each document a descriptive title and organize longer documents with meaningful headings.
- Use headings in a logical hierarchy: start with one `#` heading and do not skip heading levels.

## Writing and Formatting

- Do not impose a fixed maximum line length. Readers can wrap lines, and hard-wrapping prose makes it more difficult to edit.
- Use fenced code blocks for commands, configuration, and code examples. Add a language identifier when it is known.
- Use inline code for filenames, paths, commands, settings, identifiers, and short code references.
- Use placeholders for environment-specific values, and clearly identify values readers must replace.

## Maintenance and Validation

- Preserve existing terminology and conventions unless the task specifically calls for changing them.
- Do not claim that documentation or examples were tested unless they were actually validated.
